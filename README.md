# RAG-клиника

Локальное демо к воркшопу «Диагностика RAG-отказов». Настоящий RAG-пайплайн на GigaChat над вымышленной базой знаний маркетплейса «Полка» и пять «пациентов» — конфигураций с правдоподобными дефектами. Для каждого пациента — пошаговый разбор: жалоба → чанки → метрики → контрольный случай → промпт и конфигурация → диагноз → лечение с прогоном до и после.

Работает в двух режимах:

- **без ключа** — открываются эталонные прогоны всех пациентов из `cases/`
- **с ключом GigaChat** — любой шаг можно прогнать вживую, плюс «Лаборатория»: свой вопрос и свои настройки пайплайна

## Запуск

Нужен Python 3.10+.

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -r requirements.txt
```

```bash
.venv/bin/python server.py
```

Откроется http://localhost:8765. Переход между этапами — кнопками внизу или стрелками ← →.

## Ключ GigaChat

1. Скопируйте `.env.example` в `.env`
2. В `GIGACHAT_CREDENTIALS` вставьте ключ авторизации из личного кабинета GigaChat API (developers.sber.ru → проект → «Ключ авторизации»): строка base64, без префикса `Basic`
3. `GIGACHAT_SCOPE`: `GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` для юрлиц
4. Сертификат НУЦ Минцифры: укажите путь к нему в `GIGACHAT_CA_BUNDLE_FILE` и поставьте `GIGACHAT_VERIFY_SSL_CERTS=true` либо оставьте проверку выключенной

Проверка доступа — токен, список моделей, чат, эмбеддинги:

```bash
.venv/bin/python check.py
```

Если модели из `.env` нет в списке, который выведет `check.py`, поправьте `GIGACHAT_MODEL`, `GIGACHAT_JUDGE_MODEL`, `GIGACHAT_EMBEDDINGS_MODEL`.

## Живые прогоны всех пациентов

```bash
.venv/bin/python bake.py
```

Прогоняет каждого пациента в трёх вариантах (с дефектом, контрольный вопрос, после лечения), пишет результат в `cases/live/` и для каждого печатает, воспроизвёлся ли симптом и помогло ли лечение. В интерфейсе живой прогон включается переключателем «живой прогон».

LLM недетерминированы: симптом может не воспроизвестись с первого раза или на другой версии модели. Если по пациенту всё воспроизвелось и вы хотите, чтобы живой прогон стал эталонным:

```bash
.venv/bin/python bake.py --promote
```

После этого обновите карты пациентов:

```bash
.venv/bin/python tools/make_cards.py
```

## Как устроено

```text
corpus/              11 документов базы знаний «Полки» с метаданными (version, status, valid_from/to)
clinic/
  corpus.py          два чанкера: окно фиксированной длины и структурный (по разделам + «Документ › Раздел»)
  retrieval.py       dense (GigaChat Embeddings), BM25, hybrid (RRF), фильтр по status, HyDE, RAG-Fusion, step-back
  prompts.py         промпт «строго по фрагментам» и промпт «опирайся на свои знания»
  metrics.py         precision@k (LLM-судья), faithfulness, answer relevance — по формулам RAGAS
  pipeline.py        один прогон вопроса → полная трасса
  patients.py        пять пациентов: вопрос, конфигурация с дефектом и после лечения, диагноз
cases/               эталонные прогоны (cases/live/ — живые)
web/index.html       интерфейс
server.py            локальный сервер без внешних зависимостей
check.py  bake.py    проверка ключа и прогон всех пациентов
tools/               сборка эталонных прогонов и карт пациентов
```

**Метрики.** precision@k — доля чанков top-k, которые судья (GigaChat) признал полезными для ответа, без эталона; faithfulness — ответ разбивается на утверждения, каждое проверяется по контексту; answer relevance — по ответу генерируются три вопроса, считается средняя косинусная близость их эмбеддингов к исходному вопросу, уклончивый ответ даёт 0. Дополнительно считается precision@k по эталонной разметке — она показывается только на этапе «Диагноз».

**Эталонные прогоны.** Тексты чанков, их метаданные и разбиение — реальный вывод чанкеров. Ранги, ответы и вердикты судьи в эталонных прогонах подготовлены вручную по поведению пайплайна, чтобы демо работало без ключа и одинаково у всех. Живые прогоны GigaChat пишутся отдельно и помечаются в интерфейсе.
